# @wtf/web

`@wtf/web` - Next.js приложение WTF.

## Архитектурное решение

Приложение потребляет `@wtf/ui` и держит клиентское состояние в Zustand. Оно не импортирует persistence-слой и не выполняет доменные операции напрямую: создание и чтение задач идут через REST-контракт `@wtf/api`, а ответы валидируются Zod-схемами в локальном API client.

При первом открытии пользователь регистрируется с email и паролем, подтверждает email кнопкой из письма, затем входит с паролем; если письмо потерялось, форма входа умеет отправить подтверждение повторно. Browser client хранит JWT-сессию в `localStorage`, обновляет ее через refresh token и после входа находит или создает личный workspace `personal-{userId}`, находит или создает проект `TASKS` и загружает issue проекта. Корпоративный workspace можно создать с внутренним номером или открыть по уже выданному внутреннему номеру; если пользователь еще не участник, создается заявка владельцу. Владелец видит pending-заявки в боковой панели, подтверждает доступ и может скопировать внутренний номер из карточки workspace. Доступные workspace отображаются в сайдбаре, поэтому пользователь может быстро переключаться между личными и корпоративными задачами. Кнопка `Issue` открывает форму создания задачи, список и доска поддерживают поиск и быстрые фильтры, а board-представление позволяет переносить карточки между столбцами с записью исполнителя в activity log.

## Команды

```bash
pnpm --filter @wtf/web dev
pnpm --filter @wtf/web build
pnpm --filter @wtf/web test
```

## Переменные окружения

- `NEXT_PUBLIC_API_URL`
- `NEXT_PUBLIC_REALTIME_URL`
