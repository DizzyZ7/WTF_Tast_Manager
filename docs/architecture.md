# Архитектура WTF

## Что взято из Huly

Перед стартом изучена архитектура `github.com/hcengineering/platform` и self-hosted документация Huly. Для WTF перенесены не реализации, а принципы: монорепозиторий с явными пакетными границами, event-driven синхронизация, отдельный слой совместного редактирования, self-hosted инфраструктура с PostgreSQL, Redis и S3-совместимым хранилищем.

## Почему не копируем Huly напрямую

Huly решает более широкий набор задач и содержит несколько сервисных контуров. Для первой версии WTF выбран более компактный путь: один HTTP API как transaction boundary, отдельный realtime-пакет и чистый доменный пакет. Это снижает стоимость локального запуска и оставляет возможность выделить сервисы позже без переписывания домена.

## Границы пакетов

- `@wtf/core` - DDD-модель, value objects, доменные события, интерфейсы репозиториев. Runtime-зависимостей нет.
- `@wtf/db` - Drizzle-схемы PostgreSQL, миграции и реализации репозиториев.
- `@wtf/api` - Fastify HTTP API, JWT/OAuth2, Zod-валидация, OpenAPI.
- `@wtf/realtime` - WebSocket, Yjs-документы и event bus поверх Redis или in-memory.
- `@wtf/ui` - переиспользуемые React-компоненты без бизнес-логики.
- `@wtf/web` - Next.js приложение, потребляющее API и UI.

## Core Domain Model

```text
+-------------------+
| Workspace         |
| aggregate root    |
|-------------------|
| id, slug, name    |
| members, roles    |
+---------+---------+
          |
          | owns
          v
+-------------------+        +-------------------+
| Project           |  has   | Sprint            |
| aggregate root    +------->| entity            |
|-------------------|        |-------------------|
| key, name, status |        | goal, dates       |
+---------+---------+        +-------------------+
          |
          | contains
          v
+-------------------+        +-------------------+
| Issue             |  has   | Comment           |
| aggregate root    +------->| entity            |
|-------------------|        |-------------------|
| title, status     |        | author, body      |
| priority, assignee|        +-------------------+
| subtasks          |
| relations         |        +-------------------+
+---------+---------+  emits | Activity          |
          +--------------->  | entity/event log  |
                             |-------------------|
                             | actor, verb, data |
                             +-------------------+
```

## Контроль качества

TypeScript работает в strict mode, публичные контракты документируются JSDoc на русском, runtime-входы API валидируются Zod, доменная логика тестируется Vitest. Доступ к данным проходит через репозитории; прямой SQL не выходит за пределы `@wtf/db`.
